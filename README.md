# AI Field Guide

**Separating signal from noise in AI developer tooling.**

AI Field Guide is a curated, opinionated research project focused on AI developer tools, models, agent harnesses, and the patterns emerging around them.

## Why this exists

The space is moving too fast to track casually.

New coding agents, research agents, model wrappers, harnesses, browser tools, local runtimes, eval frameworks, and workflow products show up constantly. Most are noisy, redundant, overhyped, or too early to matter. A smaller number are genuinely important.

This project exists to find those.

It is built to answer a practical question:

> What is actually worth paying attention to?

## The key organizing idea

Most AI directories are organized the wrong way.

They start with broad categories and giant flat lists.
Real users do not think that way.

People usually start with:
- what they are trying to do
- who they are
- how much they want to spend
- which workflow they already use
- what tradeoffs they care about

So AI Field Guide is organized around:

1. **Use cases** — what job are you trying to get done?
2. **Personas** — who are you and what constraints do you have?
3. **Comparisons** — when should you choose A over B?
4. **Stacks** — which tools work well together?
5. **Tool profiles** — deeper reference pages for individual projects

## What this project does

AI Field Guide collects promising tools and systems, studies them critically, and turns those findings into a public best-of map of the space.

The goal is not to collect everything.
The goal is to curate what clears a quality bar.

## Scope

This guide may cover:

- AI coding tools
- agent harnesses
- research agents
- model tooling
- browser / tool-use systems
- memory, planning, delegation, and orchestration patterns
- benchmark and evaluation notes
- workflow UX and developer experience
- infrastructure around agentic systems

## What does not belong here

- random AI repos with no real usage
- generic wrappers with no real differentiation
- low-effort demos that teach nothing
- hype projects that do not clear a quality bar

## Sources

Projects may be surfaced through:

- hands-on exploration
- GitHub repos, issues, and comments
- Reddit
- X
- community recommendations

Internet attention is only an input. It is not the verdict.

## Evaluation lens

This guide is practical and opinionated. Evaluation will likely focus on:

- real-world usefulness
- reliability
- UX / developer experience
- simplicity vs complexity
- extensibility
- novelty
- production readiness
- what is worth copying

The framework will evolve as the guide grows.

## Freshness matters

A smaller guide with current, honest entries is more valuable than a giant stale directory.

Each reviewed project should eventually include:
- status: Active / Watching / Archived / Dead
- last verified date
- honest failure modes
- clear "best for" and "not ideal for" judgments

## Structure

- `use-cases/` — primary navigation by job to be done
- `personas/` — recommendations by user type
- `comparisons/` — head-to-head pages
- `stacks/` — recommended tool bundles
- `tools/` — deep project pages
- `rankings/` — best-of lists and category summaries
- `benchmarks/` — benchmark and eval notes
- `meta/` — thesis, organization principles, freshness policy
- `templates/` — repeatable review templates

## Intended output

Over time, this project should produce:

- a curated best-of list
- project notes and comparisons
- reusable evaluation templates
- a clearer thesis on where AI tooling is actually going

## Status

Early. The structure is being set up now.

This is not a finished publication yet. It is the start of a public field guide.
