# AI Field Guide

**A practical guide for indie hackers using AI to ship products faster.**

AI Field Guide is a curated, opinionated project about choosing the right AI tools and stacks for real product work.

**Current v1 focus:** helping indie hackers choose the right AI tools and stacks to ship faster, validate faster, and waste less money.

## Why this exists

The space is moving too fast to track casually.

New coding agents, model wrappers, research tools, and workflow products show up constantly. Most are noisy, redundant, overhyped, or too early to matter.

Indie hackers do not need more generic "top 50 AI tools" lists.
They need help answering simpler questions:

- What should I actually pay for?
- What stack should I start with?
- What is good enough to ship with?
- What is overkill before revenue?
- Which tools help me launch faster instead of just giving me more setup?

This project exists to answer those questions.

## The key organizing idea

Most AI directories are organized the wrong way.

They start with giant flat lists and vague categories.
Real users do not think that way.

Indie hackers usually start with:
- what they are trying to build
- how much they want to spend
- whether the tool helps them ship faster
- whether the stack stays sane after launch

So AI Field Guide is organized around:

1. **Personas** — who is this guide for?
2. **Stacks** — what is the default setup?
3. **Use cases** — what are you trying to get done?
4. **Tools** — what role does each tool play?

## What this project does

AI Field Guide collects promising tools and systems, studies them critically, and turns those findings into practical recommendations.

The goal is not to collect everything.
The goal is to help indie hackers choose a small, useful stack that actually helps them build and launch.

## Current focus

The long-term scope is broad, but the current focus is intentionally narrower.

Right now, AI Field Guide is mainly about:

- AI coding tools for indie hackers
- practical stacks that help ship products faster
- use-case-driven recommendations
- cost discipline and avoiding tool overlap
- workflow choices that help get from idea to launched product

Broader coverage can come later.

## What does not belong here

- random AI repos with no real usage
- generic wrappers with no real differentiation
- low-effort demos that teach nothing
- hype projects that do not clear a quality bar

## Sources

Projects may be surfaced through:

- hands-on exploration
- GitHub repos, issues, and comments
- Reddit
- X
- community recommendations

Internet attention is only an input. It is not the verdict.

## Evaluation lens

This guide is practical and opinionated. The main questions are:

- does this help an indie hacker ship faster?
- is the cost justified early?
- does it reduce real bottlenecks?
- is it simpler than the alternatives?
- does it stay useful after the first week of hype?
- is it worth copying into a real working stack?

## What this guide tries to avoid

- tool sprawl
- fantasy stacks
- expensive overlap before revenue
- flat directories with no judgment
- pretending every tool is equally good
- treating AI output as progress when nothing has actually shipped

## Structure

The repo is intentionally lean for now.

- `personas/` — who this guide is for
- `stacks/` — default tool bundles and budget lanes
- `use-cases/` — practical jobs like building an app or refactoring a codebase
- `tools/` — deep pages for the core tools that keep showing up

Everything else can come later if it earns its place.

## Intended output

For now, this project should produce:

- clear recommendations for indie hackers
- small, useful stacks
- practical use-case pages
- honest tool pages
- a better default answer to: "what should I use if I want to build and launch without wasting money?"
