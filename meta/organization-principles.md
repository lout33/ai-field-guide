# Organization Principles

AI Field Guide is organized around **how people choose tools in real life**.

## Core rule

People do **not** start with broad categories like:
- productivity
- AI assistant
- developer tools

People start with:
- what they are trying to do
- who they are
- how much they want to spend
- what they already use
- what they want to avoid

So this guide should be organized in this order:

1. **Use case first**
   - build a web app
   - refactor a codebase
   - run deep research
   - automate browser work
   - transcribe and summarize meetings

2. **Persona second**
   - solo developer
   - startup team
   - enterprise buyer
   - student
   - content creator

3. **Comparison third**
   - when to use A vs B
   - best for / not ideal for
   - cost, reliability, workflow fit

4. **Stacks fourth**
   - which tools work well together
   - common pairings
   - budget-aware setups

## Anti-patterns to avoid

- giant flat lists of tools
- vague categories with no user intent
- no freshness or maintenance signal
- no failure modes
- no pricing clarity
- no opinionated verdict
- pretending every tool is equally good

## Required signals for each reviewed tool

Each tool entry should try to include:
- primary use case
- best for
- not ideal for
- pricing / cost model
- status: active / watching / archived
- last verified date
- notable strengths
- notable failure modes
- what makes it different from ChatGPT / Claude directly
- whether it is still worth using after 30 days

## Publishing rule

This project should prefer:
- fewer entries
- stronger judgment
- higher freshness
- better comparisons

over exhaustive coverage.
